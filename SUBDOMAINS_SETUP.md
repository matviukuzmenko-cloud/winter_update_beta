# Поддомены Silva Quieta

Подготовлены три самостоятельных статических проекта:

- `ailab/` — Silva AI Lab, отдельный интерфейс чата Silva.
- `community/` — Silva Community: публичная лента, публикации с фотографиями, комментарии, лайки и жалобы.
- `os-site/` — промо-страница Silva OS для `os.silvaquieta.com`.

Отдельные домены покупать не нужно: поддомены создаются DNS-записями в панели, где управляется DNS домена `silvaquieta.com`. Нужен доступ к этой DNS-панели.

Каталог рабочей копии не является Git-репозиторием. Рекомендуемый простой вариант — опубликовать каждый сайт через GitHub Pages из отдельного репозитория и поместить содержимое соответствующего каталога в корень репозитория. В каждом уже есть свой `CNAME`.

## GitHub Pages и DNS

1. Создайте репозитории `silvaquieta-ailab`, `silvaquieta-community` и `silvaquieta-os`.
2. Скопируйте содержимое `ailab/` и `community/` в корни соответствующих репозиториев. Для `silvaquieta-os` скопируйте содержимое `os-site/` в корень и поместите содержимое `silva-os/` в подпапку `app/` (чтобы адрес `https://os.silvaquieta.com/app/` открывал PWA). Дополнительно скопируйте в корень репозитория `silvaquieta-os` файлы `icon.svg`, `icon-192.png` и `icon-512.png` из корня сайта. Публикуйте основную ветку из корня каждого репозитория через **Settings → Pages**.
3. В настройках Pages укажите `ailab.silvaquieta.com`, `community.silvaquieta.com` и `os.silvaquieta.com`; подтвердите включение HTTPS после появления DNS-записей.
4. В DNS-зоне `silvaquieta.com` добавьте три записи CNAME:

   | Тип | Имя | Значение |
   |---|---|---|
   | CNAME | `ailab` | `matviukuzmenko-cloud.github.io` |
   | CNAME | `community` | `matviukuzmenko-cloud.github.io` |
   | CNAME | `os` | `matviukuzmenko-cloud.github.io` |

   Если в GitHub Pages для этих репозиториев отображается другой адрес GitHub Pages, используйте его как значение CNAME. Удалите конфликтующие записи только для имён `ailab`, `community` и `os`.
5. Основной сайт содержит ссылки на поддомены в шапке и футере. Они начнут открываться после назначения доменов репозиториям и публикации.

## Перенос DNS в Cloudflare для WAF (необязательно)

Публичная делегация сейчас использует NS `launch1.spaceship.net` и `launch2.spaceship.net`; снимок SpaceShip показывает следующие восемь записей. Если переносите DNS-зону в Cloudflare, создайте их до смены NS:

| Имя | Тип | Значение | Proxy при первичной проверке |
|---|---|---|---|
| `@` | `A` | `185.199.108.153` | DNS only |
| `@` | `A` | `185.199.109.153` | DNS only |
| `@` | `A` | `185.199.110.153` | DNS only |
| `@` | `A` | `185.199.111.153` | DNS only |
| `www` | `CNAME` | `matviukuzmenko-cloud.github.io` | DNS only |
| `ailab` | `CNAME` | `matviukuzmenko-cloud.github.io` | DNS only |
| `community` | `CNAME` | `matviukuzmenko-cloud.github.io` | DNS only |
| `os` | `CNAME` | `matviukuzmenko-cloud.github.io` | DNS only |

На снимке нет MX/TXT/CAA-записей. Если это полный актуальный список зоны и почта на домене не используется, перенесите ровно эти восемь записей. Перед сменой NS всё равно проверьте в SpaceShip, что нет дополнительных записей, доменной почты или TXT-проверок сторонних сервисов.

Порядок безопасного включения:

1. Добавьте домен в Cloudflare и импортируйте перечисленные записи, сначала оставив их в режиме **DNS only**.
2. Сверьте полный список с актуальной зоной SpaceShip; проверьте сайт, все поддомены, почту и проверочные TXT-записи.
3. Скопируйте назначенные Cloudflare авторитетные NS и вручную укажите их в настройках домена SpaceShip. Не используйте NS из примеров или чужого аккаунта.
4. Дождитесь статуса Active в Cloudflare и проверьте HTTPS и каждый поддомен. Только после этого рассмотрите включение proxy/WAF.
5. GitHub Pages обслуживает origin через HTTPS. Перед включением proxy проверьте режим SSL/TLS **Full (strict)**, сертификат origin, custom domains и доступность всех приложений. Если HTTPS или GitHub Pages начинает работать некорректно, верните запись в **DNS only**.
6. После включения proxy добавьте точечные Cloudflare WAF/rate-limit правила для API и honeypot. Не блокируйте всех посетителей по User-Agent и не включайте без проверки правило, способное закрыть доступ к статическим страницам.

Worker в `wrangler.toml` пока не привязан к custom route сайта. После активации Cloudflare добавьте в `wrangler.toml` маршрут (перед deploy):

```toml
[[routes]]
pattern = "silvaquieta.com/api/internal/*"
zone_name = "silvaquieta.com"
```

Затем разверните Worker снова. Honeypot на Worker начнёт принимать запросы с `silvaquieta.com` только после настройки Cloudflare DNS/proxy и этого отдельного route; до этого `robots.txt` лишь просит совместимых роботов не обращаться к этому пути и не является блокировкой. Не добавляйте маршрут для всего сайта: статику продолжают обслуживать GitHub Pages.

Страница Silva OS ведёт на приложение как устанавливаемое PWA. На iPhone/iPad откройте его в Safari и выберите **Поделиться → На экран «Домой»**; на Mac и Windows установите через меню поддерживаемого браузера. Нативные `.dmg`, `.msi`/`.exe` и iOS App Store-сборки в проекте пока не опубликованы, поэтому кнопки загрузки ведут к веб-приложению, а не к несуществующим установщикам.

## Что ещё нужно сделать

- **Домен/DNS:** ничего больше покупать или регистрировать не нужно. Создайте три CNAME-записи выше у своего DNS-провайдера (это может быть регистратор домена или Cloudflare — смотря где сейчас управляются DNS-записи).
- **GitHub:** опубликуйте файлы трёх каталогов в отдельных репозиториях, настройте Pages и укажите соответствующий custom domain в настройках каждого репозитория.
- **Supabase:** примените обе миграции сообщества, проверьте `supabase-config.js`, публичное чтение ленты, публикации, Storage и настройки входа.
- **AI Lab:** после публикации обновите Worker командой `npx wrangler deploy`, чтобы он применил CORS-разрешение для `https://ailab.silvaquieta.com`.
- **Проверка:** дождитесь обновления DNS, включите HTTPS в GitHub Pages и проверьте оба адреса по HTTPS с компьютера и телефона.

## Включение AI Lab

AI Lab отправляет вопросы существующему Worker по адресу `https://flora-anotomy-ai.ukrainman21012.workers.dev`. В `worker.js` добавлен точный разрешённый Origin `https://ailab.silvaquieta.com`; после публикации требуется развернуть Worker:

```sh
npx wrangler deploy
```

Чат использует существующую Gemini-конфигурацию, серверный лимит запросов и правила CORS Worker. История диалога хранится в локальном хранилище браузера отдельно для каждого языка.

## Включение сообщества

1. Выполните в Supabase SQL Editor файлы [`supabase/migrations/20261106_silva_community.sql`](./supabase/migrations/20261106_silva_community.sql), затем [`supabase/migrations/20261106_silva_community_features.sql`](./supabase/migrations/20261106_silva_community_features.sql). Второй файл добавляет профили с аватарами, сохранённые публикации, просмотр своих записей и защищённое редактирование/удаление собственных публикаций и ответов.
2. В **Authentication → URL Configuration → Redirect URLs** добавьте `https://community.silvaquieta.com/**`. Вход использует тот же Supabase-проект и тот же алгоритм имени аккаунта, что и основной сайт; на новом поддомене пользователю потребуется войти отдельно.
3. Откройте `community.silvaquieta.com`. Для загрузки конфигурации Supabase страница читает опубликованный ключ из `https://silvaquieta.com/supabase-config.js`. Секретный `service_role` ключ никогда не используется в браузере.
4. Проверяйте поступившие жалобы в таблице `community_reports` через Supabase Studio/SQL Editor с административным доступом. Публичный и пользовательский клиент не имеет прав читать жалобы.

Фотографии публикаций хранятся в публичном Storage bucket `silva-community` (до 5 МБ; JPEG, PNG, WebP): загрузка разрешена только вошедшим пользователям в собственную папку. До публикации предупреждайте пользователей, что загруженные фотографии и текст видны всем. Пароли и личные данные в публикациях размещать не следует.

## Проверки после публикации

- Откройте обе страницы на телефоне и компьютере и проверьте HTTPS.
- В AI Lab проверьте, что статус Silva стал доступным, и отправьте тестовый вопрос на русском, украинском и английском.
- В Community проверьте публичное чтение ленты, регистрацию/вход, смену аватара и ника, создание и редактирование записи с фото, лайк, закладки, ответы и жалобу.
- В Supabase убедитесь, что жалоба видна только администраторам, а незалогиненный посетитель не может публиковать, голосовать или загружать фото.
